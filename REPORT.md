# REPORT — Лаб 4: мобильное приложение

## 1. Тема и обоснование
Выбран **вариант Б**: конвертер валют из Лаб 3 перенесён на Android и расширен экранами сравнения
курса за неделю и за месяц. Тема даёт понятный показатель для аналитики (курс валютной пары), а
официальный источник BNM публикует курс на любую прошлую дату, поэтому история доступна сразу после
установки приложения.

## 2. Язык Лаб 3 и язык Лаб 4
| Лаба | Язык | Стек |
|---|---|---|
| Лаб 3 | Python 3.12 | Tkinter, desktop |
| Лаб 4 | **Kotlin 2.0** | Android, Jetpack Compose, Material 3, корутины |

Язык сменён. Код Лаб 3 не переиспользовался: модули разбора XML, конвертации, кэша и статистики
написаны заново на Kotlin, с другой архитектурой (чистый модуль `core` + Android-модуль `app`,
`suspend`-функции вместо синхронных вызовов, `BigDecimal` вместо `Decimal`).

## 3. Источник исторических данных и его ограничения
Источник — XML Национального банка Молдовы:
`https://www.bnm.md/en/official_exchange_rates?get_xml=1&date=DD.MM.YYYY`.

История собирается **множественными запросами по датам** с **накоплением в локальном кэше**
(комбинация подходов):
- для экрана «Неделя» запрашиваются рабочие дни за 7 дней (5 запросов), для «Месяца» — за 30 дней (~22 запроса);
- каждый успешный ответ сохраняется в файл `rates/ГГГГ-ММ-ДД.xml`; прошлые даты при следующем открытии
  берутся из кэша без сети, повторно запрашивается только сегодняшний день;
- субботы и воскресенья пропускаются (BNM в эти дни курс не публикует), праздники обрабатываются как
  пустой ответ.

Ограничения:
- первый запуск месячного экрана делает около 22 запросов, это занимает несколько секунд;
- без сети на первом запуске истории нет: показывается сообщение, а не пустой график;
- если сеть пропала посреди загрузки, остальные даты берутся из кэша, а недостающие дни показываются
  в уведомлении «Нет данных за N раб. дн.»;
- курс публикуется около 13:00 по Кишинёву, поэтому утром «сегодняшняя» точка может отсутствовать.

## 5. Что ИИ сгенерировал корректно, а где ошибся
**Корректно с первого раза:** разбор XML BNM с номиналом (RUB за 100 единиц), кросс-курс через MDL,
валидация суммы (минус, ноль, буквы, запятая), статистика периода, логика выходных и кэша. После исправлений ниже
проходят все 33 unit-теста.

**Ошибки ИИ и исправления:**
| Где | Что было не так | Как исправлено |
|---|---|---|
| `BnmXmlParser` | Включалась защита от XXE через `setFeature(disallow-doctype-decl)`. Парсер XML в Android такую настройку не поддерживает и бросает исключение, поэтому **любой** ответ BNM на телефоне считался бы некорректным. На JVM тесты это не ловили. | Настройка обёрнута в `runCatching`, отдельный коммит |
| `ConverterTest.roundTripKeepsAmount` | Тест сравнивал результат через `setScale(0)` без округления, что бросает `ArithmeticException` для дробной суммы | Сравнение с допуском 0,01 |
| `core/build.gradle.kts` | `jvmToolchain(17)` требовал скачать JDK 17, которого нет в окружении | Заменено на `jvmTarget = 17` |
| `ConverterScreen` | `supportingText = state.inputError?.let { { Text(it) } }` — лямбда без `@Composable`-типа | `supportingText = { state.inputError?.let { Text(it) } }` |
| _дополнить по результатам сборки в Android Studio_ | | |

## 6. Насколько сложнее или проще работать с ИИ на новом языке
_Черновик, дополнить своими словами._

Работать с ИИ на Kotlin оказалось **проще в генерации и сложнее в проверке**, чем на Python.
ИИ хорошо знает Kotlin и Jetpack Compose и сразу выдаёт идиоматичный код (data-классы, `sealed interface`,
корутины, `StateFlow`). Но на незнакомом языке труднее заметить ошибку при чтении: например, проблему с
`setFeature` на Android нельзя увидеть ни в коде, ни в тестах на JVM, она проявляется только на устройстве.
Поэтому главный вывод — на новом языке нельзя полагаться на «выглядит правильно»: логику надо выносить в
модуль, который покрывается тестами, а платформенный код обязательно проверять запуском на эмуляторе.
Кроме того, сборка Android-проекта (Gradle, версии AGP, Kotlin и Compose) — отдельный источник ошибок, где
ИИ помогает подобрать совместимые версии, но окончательно их проверяет только синхронизация в Android Studio.
